# Proposal: Student My Timetable UI

## Why

Students currently have no view of their own cohort's weekly schedule with live replacement status. FR 1.2 (view the full timetable), FR 1.3 (view request status), and FR 1.4 (strictly view-only) require a dedicated student timetable page. The existing lecturer **My Timetable** page is unsuitable: it shows a *lecturer's* mixed-cohort teaching schedule and exposes lecturer-only actions ("Replace Now", "Cancel Class") that violate FR 1.4 for students.

Adding this page also forces two long-overdue cleanups mandated by CodingMAIN §10.0 rule #6 (promote-on-3rd-duplication):

1. **3-copy promotion (near-total).** The read-only legend bar markup and ~480 lines of inline CSS (legend + summary-card-color + modal-shell + the entire timetable-grid CSS: semester-bar, time-column, hour-header, hour-cells, event-block) are duplicated byte-for-byte between `MyTimetable-UI-design-template` and `CohortTimetable-UI-design-template`; the new student page is the 3rd copy. Rule #6 forbids leaving 3 copies — they must be promoted to a shared partial + `theme.css` now, with the two existing pages refactored to consume them. (Two intentional exceptions stay page-specific — see Out of scope.)
2. **Semester-date drift.** `MockData.semester` (canonical, start **2026-08-31**) has existed since the centralized-mock-data change, but `MyTimetable` and `CohortTimetable` still generate their week calendar from a stale inline `new Date(2026, 5, 15)` (15-Jun) — in TWO places each (`weekData` builder + `currentWeekIndex()`) — and hardcode a stale chip text. The student page will read `MockData.semester` fully; the two existing pages will be migrated to derive their week calendar + chip from `MockData.semester` so all three pages agree.

## Scope

### In scope

1. **New Blade template** `resources/views/ui-design-templates/student-my-timetable-UI-design-template.blade.php` — `@extends('layouts.ui-template', ['activeNav' => 'my-timetable'])`, `@section('title', 'My Timetable')`. A view-only weekly grid (time × day) for the logged-in student's own cohort, with the 4-item read-only legend, 5 summary cards, a view-only class-detail modal, and a week picker (arrows + `<select>`, localStorage persistence).
2. **New route** `GET /student-my-timetable-ui` in `routes/web.php`, returning the template with `$activeNav = 'my-timetable'` and a reduced `$navItems` set (see item 8).
3. **Event data source — `MockData.cohortTimetable` (NOT `MockData.myTimetable`).** The student's cohort is hardcoded to **RSD3(S1)G2** in the mock phase. The page reads `MockData.cohortTimetable.rsd3g2Base` (7 base events) + `MockData.cohortTimetable.rsd3g2Flags` (per-week replacement/pending overrides) and rebuilds the 14-week schedule, deriving a **local per-week copy** (`slice()`) before any per-week mutation — `MockData` is treated as immutable (CodingMAIN §10.3).
4. **New mock-data section** `MockData.studentTimetable = { activeCohort: 'rsd3s1g2', cancelledFlags: { 4: ['BMIT7070', 'BMIT7071', 'BMIT7072', 'BMIT8080', 'BMIT7073', 'BMIT7074', 'BMIT7075'], 5: ['BMIT8080'], 6: ['BMIT7073'] }, notificationCount: 3 }` — a read-only registry of classes cancelled per week + a notification badge count. **Week 4 cancels ALL 7 base events** to ensure the empty-state message (item 17) can be triggered — this is the only week where `visibleEvents.length === 0`. Weeks 5–6 cancel 1 event each (realistic partial cancellation). The page filters out any event whose `code` is in `cancelledFlags[currentWeek]` (and any event with `status === 'cancelled'`, defensively) **before** render and **before** counting summary cards. The `notificationCount` drives the nav-bar notif-badge (replacing hardcoded `3` — see item 20). *(Declarative edit in same file: update the `mock-data.js` §2.2 `holidays` header comment, which currently claims "CONSUMED BY CohortTimetable ONLY" — after this change `MockData.holidays` is also consumed by the student page's conflict derivation, so the comment is updated to list the new consumer.)*
5. **Status rendering.** Cell badges use the canonical read-only legend map (CodingMAIN §10.0 table A): Normal=`--color-secondary`, Replacement=`--color-primary`, Pending=`--color-tertiary`, Conflict=`--color-error`. Conflict is **derived** from `MockData.holidays` (week-3 Thursday) — an event falling on a holiday renders as conflict — not stored on the event. This `MockData.holidays`-driven conflict path is **NEW behavior** introduced by the student page (CohortTimetable computes holidays inline; MyTimetable's holiday code is dead). **Cancelled classes are fully hidden** (no legend swatch, no summary card, never counted) — this is a **design decision** for the mock phase (no FR mandates it), chosen to keep the student's reading view uncluttered.
6. **5 summary cards** via `@include('partials.ui-summary-bar')` with classes identical to MyTimetable (`.card-total`, `.card-hours`, `.card-replacement`, `.card-pending`, `.card-conflict`). The 5th card label is **"Class Hours"** (renamed from "Teaching Hours"); the `.card-hours` class name is unchanged. Counts reflect the post-cancelled-filter dataset.
7. **View-only modal.** Footer shape from CohortTimetable (Close ✕ only — no "Replace Now", no "Cancel Class", no cancel-confirm overlay). Field list from MyTimetable **minus** Cohort/Total-Students (cohort is fixed): **Code, Name, Class Type (L/T), Lecturer, Venue, Day, Date, Time, Status, Remarks** (+ Requested At/By when status is pending). Close triggers use the shared `closeOnEsc(closeModal)` + `closeOnOverlayClick` helpers from `ui-common.js` (rule #6 — no third inlined ESC handler). **FR 1.4 enforcement = UI exclusion (in-scope, this change).**
8. **Reduced student nav (DRY + href-correct).** Parametrize the shared `resources/views/partials/ui-nav-bar.blade.php` to accept a `$navItems` array of `{key,label,href}` items, **defaulting to the current 5 items with current hrefs** (so existing pages pass only `$activeNav` and are unchanged). The student page passes 3 items **with student-correct hrefs**: Dashboard→`/dashboard`, My Timetable→`/student-my-timetable-ui`, Replacement History→`/my-request-history-ui` — omitting **Replacement Arrangement** (students cannot create requests) and **Cohort Timetables**. *Cohort Timetables omission rationale:* per user decision (mock phase — students should not browse *other* cohorts' timetables); the student's own-cohort view is delivered by this Student My Timetable page (FR 1.2). The CodingMAIN §6 "View cohort timetables ✅ Student" capability is satisfied by this own-cohort page; the cross-cohort faculty-browse interface is a lecturer/PL function to be role-split in Sprint 3 RBAC. *(Open documentation note: §6 RBAC matrix wording may need tightening in a later change to distinguish own-cohort view vs cross-cohort browse.)* This fixes the FR 1.4 nav gap (a student clicking "My Timetable" lands on the **student** page, not the lecturer page). No student-specific nav partial is created (rule #3 — no copy-paste).
9. **Promote-on-3rd-duplication (rule #6) — near-total promotion:**
   - **a.** Create `resources/views/partials/ui-legend-bar.blade.php` containing the 4 read-only legend items with canonical token-mapped swatches. Refactor `MyTimetable`, `CohortTimetable`, and the new Student page to `@include('partials.ui-legend-bar')`.
   - **b.** Move **legend CSS** (`.legend-bar`, `.legend-item`, `.legend-swatch`) from inline → `theme.css`.
   - **c.** Move **summary-card color CSS** (`.summary-card.card-total/.card-replacement/.card-pending/.card-conflict/.card-hours` value-color + variant overrides) from inline → `theme.css`.
   - **d.** Move **modal-shell CSS** (`.modal-overlay`, `.modal`, `.modal-header`, `.modal-title`, `.modal-status-badge` + `.normal/.replacement/.pending/.conflict` variants, `.modal-close`, `.modal-body`, `.modal-field`, `.field-label`, `.field-value`, `.modal-footer`, `.btn-close-modal`, `@keyframes modalIn`) from inline → `theme.css`. **Divergence note:** MyTimetable's `.modal-footer` uses `justify-content: space-between` (footer has left+right children for Replace/Cancel buttons); CohortTimetable's (and the student page's) uses `justify-content: flex-end` (single Close button). Standardize `.modal-footer { justify-content: flex-end; }` in `theme.css`; **MyTimetable keeps a 1-line page-local override** `.modal-footer { justify-content: space-between; }` after promotion.
   - **e.** Move **semester-bar / week-picker CSS** (`.semester-bar`, `.week-arrow` + `:hover`/`:disabled`/`:disabled:hover`, `.week-select` + `option` + `html.dark .week-select`, `.semester-bar select:not(.week-select)`) from inline → `theme.css`. Standardize the `.week-select` `min-width` divergence (MyTimetable 140 vs CohortTimetable 160) to **160** in the shared class.
   - **f.** Move **time-column CSS** (`.time-col`, `.day-label`, `.date-label`, `.holiday-label`, `.time-col.today`/`.holiday-col`/`.sunday-col` + nested label overrides) from inline → `theme.css`.
   - **g.** Move **hour-header CSS** (`.hour-header`, `.hour-top`, `.hour-bottom`) from inline → `theme.css`.
   - **h.** Move **hour-cell + event-block CSS** (`.hour-cell`, `.sunday-slot`, `.holiday-slot`, `.event-public-holiday`, `.event-block` + `:hover`/`:active`, `.event-normal`/`.event-replacement`/`.event-pending`, `.sunday-slot .event-block`/`.holiday-slot .event-block` overrides, `.ev-code`/`.ev-venue`/`.ev-time`/`.ev-note`, `.cell-empty`, `.timetable tr:last-child`) from inline → `theme.css`.
   - **i.** **Delete dead `.today-highlight` CSS** (`rgba(26,95,180,0.04) !important`) from both MyTimetable and CohortTimetable — it is unused by either JS (rule-#1 hardcoded-rgba violation) and must NOT be recreated on the student page.
   - Page-specific modal action-button CSS (`.btn-replace-now`, `.btn-cancel-class`, `.cancel-overlay` + sub-classes) **stays inline in `MyTimetable`** — it is not duplicated elsewhere.
10. **Semester-chip + week-calendar fix on all 3 pages.** All three pages render the chip text and build `weekData` from `MockData.semester` (start **2026-08-31**, chip "202605 Semester · 31-Aug-2026 ~ 06-Dec-2026"), eliminating the stale 15-Jun-2026 drift. In `MyTimetable` and `CohortTimetable`, **both** occurrences of the stale date are replaced: the `weekData` builder AND `currentWeekIndex()` are driven by `new Date(MockData.semester.startDate)`; the hardcoded chip `<span>` is populated from `MockData.semester.chipText`. (Their inline *event* data stays put — see Out of scope.)
11. **Cohort display.** The fixed cohort "RSD3(S1)G2" is shown in the page header as a second `.semester-chip`-styled pill (reusing the existing shared `.semester-chip` class from `theme.css` — no new class) alongside the semester chip. The per-cell/per-modal `cohort` field is dropped (it is always the student's own cohort).
12. **Page changelog** `page-changelogs/student-my-timetable-ui-changelog.md` (stub created before this proposal froze; populated during apply).
13. **"Today" button.** An icon button (target/bullseye) placed inside `.semester-bar` after the `›` arrow. One-click jumps to the current week (`currentWeekIndex()`), rebuilds the grid, and saves to localStorage. Provides instant "where am I this week?" navigation without clicking through 14 weeks.
14. **Week-of-semester subtitle.** A `<div class="week-subtitle">` between the semester bar and the grid, showing `"Week 3 of 14 · 15 Sep – 21 Sep"`. Updated on every week change. Reduces cognitive load — students see position-in-semester and actual date range at a glance.
15. **Week `<select>` date ranges.** The `<option>` text in the week dropdown changes from `"Week 1"` to `"Week 1 (1 Sep – 7 Sep)"`. Uses `weekData[i].start` / `weekData[i].end` formatted as `d-MMM` (no year, no leading zero) via a helper `fmt(d)`. Students think in dates, not week numbers. The `weekData` rebuild (frozen item 10) already produces per-week start/end dates — this surfaces them in the dropdown.
16. **Mini 14-week heatmap bar.** A compact horizontal bar of 14 small clickable squares above the timetable grid. Each square is color-coded by event density for that week: green (`--color-secondary`) = all normal, blue (`--color-primary`) = has replacement, yellow (`--color-tertiary`) = has pending, red (`--color-error`) = has conflict, `--color-surface-variant` = no events (all cancelled). **Priority when multiple statuses coexist in a week:** red (conflict) > yellow (pending) > blue (replacement) > green (all normal) > grey (no events). Click a square → jump to that week. Gives instant "scan the semester" overview without clicking through each week individually.
17. **Empty-state message.** When the cancelled-filter produces zero `visibleEvents` for a week, display a friendly `"No classes this week"` message instead of a blank grid. Prevents "is it broken?" confusion. Pattern borrowed from CohortTimetable's empty-state handling.
18. **Keyboard navigation.** ArrowLeft/ArrowRight keys navigate between weeks (same as clicking `‹`/`›`). Enter key on a focused `.event-block` opens the modal. Provides basic keyboard accessibility for power users. Arrow listeners are bound to `document`; when the `<select>` dropdown is focused, the browser consumes arrow keys natively — no conflict. *(Mock-phase only — full WCAG screen-reader and focus-management compliance deferred to Sprint 3 accessibility pass.)*
19. **Modal request-status timeline.** For events with `status === 'pending'`, the modal body includes a 3-step visual status bar: **Submitted** ✓ → **Under Review** (active, highlighted) → **Awaiting Replacement** (waiting). This is a visual-only approximation of the future backend workflow (actual state model: `pending → approved/rejected`); steps will be refined when the approval pipeline lands in Sprint 3. Purely visual; no new data needed — derives from existing `status` field.
20. **Dynamic notification count.** The nav-bar `.notif-badge` count is read from `MockData.studentTimetable.notificationCount` instead of the hardcoded `3`. The nav partial gains a `$notifCount` variable (default `3` for backward compatibility). **The layout file `resources/views/layouts/ui-template.blade.php` must be updated** to accept and forward `$notifCount ?? 3` to the `@include('partials.ui-nav-bar', ...)` call. The student page passes the real count via `@extends`. When FR 1.5 (email notifications) lands in Sprint 3, this lights up with real data.
21. **Event `.meta` pocket.** Each event in the local `eventsByWeek` reconstruction gets an optional `meta: {}` property (empty object by default). Currently unused — the modal does not read it. When the backend later adds fields (e.g., `materialUrl`, `roomCapacity`, `attendanceRequired`), the modal can read `event.meta.materialUrl` without a data-structure refactor. Zero cost now, saves refactoring later.
22. **Semester progress bar.** A thin CSS-width bar (not Unicode characters) under the semester chip: `<div class="progress-fill" style="width: ${pct}%">` where `pct = ((currentWeek+1) / MockData.semester.weeks) * 100`. Label text: `"Week 5 of 14"` + percentage. Updates on week change. Students get a visual sense of where they are in the semester.
23. **Week-change transition.** Subtle CSS fade animation on the timetable grid when switching weeks — the grid fades out briefly (100ms) then fades in (200ms). Prevents the jarring "instant swap" feel. Pure CSS (`opacity` transition on `.grid-scroll`), no JS overhead beyond toggling a class.
24. **Event hover tooltip.** On hover, event blocks show a CSS `::after` tooltip with the full course name and venue (e.g., "Object-Oriented Programming · Lab 3.01"). Students scanning the grid don't have to click every event to see details. Tooltip follows cursor, hidden on mouseout. Uses only `data-name` and `data-venue` attributes set during `buildTimetable()`.
25. **Copy course code.** Click the `.ev-code` label inside any event cell → copies the course code to clipboard and shows a brief toast ("Copied BMIT7070"). Students often need to search the code in the student portal. Uses `navigator.clipboard.writeText()` + a 1.5s auto-hiding toast element.
26. **Smooth scroll to grid.** When the user clicks the Today button (item 13) or a heatmap square (item 16), the timetable grid auto-scrolls into view via `document.querySelector('.grid-wrapper').scrollIntoView({ behavior: 'smooth', block: 'start' })`. On smaller screens the grid is below the fold — this prevents the user from clicking a heatmap square, nothing visually changing, and having to manually scroll down.

### Out of scope

- **Migrating `MyTimetable` / `CohortTimetable` inline *event* data to `MockData`.** Only their week calendar + chip migrate in this change; their event arrays (`eventsData` / `facultyData` + `allEvents`) stay inline. Full event-data migration is a separate change.
- **CohortTimetable's inline holiday computation** (`holiday: d === 3 && w === 3`, baked into its `weekData` day objects) is NOT refactored by this change — only its chip + week-calendar dates migrate. The student page introduces the `MockData.holidays`-driven conflict path as a new pattern; CohortTimetable keeps its inline holiday logic for now.
- **CohortTimetable's `.badge-*` variants** (`.badge-normal`/`.badge-replacement`/`.badge-pending`/`.badge-conflict`) — page-specific (used only in its modal body `mdlStatusBadge`), not duplicated onto the student page (student modal uses `.modal-status-badge` only, like MyTimetable). The pre-existing `.badge-replacement` gold `#d4a017` (rule #1 + #2 violation) is a **known issue deferred** to a dedicated CohortTimetable cleanup; the student page introduces no such hardcoded color.
- **Backend / auth / RBAC middleware.** Routes stay public like the other `-ui` mocks. **NFR 2.1** (role middleware) and **NFR 3.4** (post-login role redirect) defer to Sprint 3. **FR 1.4** (view-only) is enforced at the UI level (in-scope, item 7) — no write actions rendered.
- **FR 1.5** (email on timetable updates) — backend (queue/mail); not mock-phase.
- **Rejected-status display on the timetable.** A rejected request leaves the original class still scheduled as `normal` (the slot state machine in CodingMAIN §3 governs the *replacement-arrangement slot grid*, not the timetable event model; the timetable event model only has `normal`/`replacement`/`pending`). No `rejected` event status exists in the data model — therefore no `rejected` cell to render. Rejected status is surfaced on the separate **Replacement History** page (already in the reduced student nav).
- **Stale 15-Jun `semester-chip` text on the three other pages** (`replacement-arrangement`, `replacement-home`, `my-request-history`) remains for a separate change — not an oversight, just out of this change's scope.
- **New dependencies.** Reuse Flux/Livewire/Tailwind + `theme.css` + `ui-common.js` + `mock-data.js` only.
- **Full WCAG accessibility.** Keyboard nav (item 18) is mock-phase only (basic arrow/enter). Full screen-reader support, ARIA roles, focus trapping in modals, and compliance with WCAG 2.1 AA defer to Sprint 3 accessibility pass.
- **`MockData.myTimetable`** is not touched — it remains the lecturer's mixed teaching schedule; the student page does **not** read it.
